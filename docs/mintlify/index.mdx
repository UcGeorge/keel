Every project has one person who really knows how to deploy it: the order of
the commands, the CLIs that need to be installed, the six environment
variables, the section of the README that says *"then run this script"*.
When that person is on holiday, nobody deploys.

Keel moves that knowledge out of people's heads and into a file. A
`keel.yaml` at the root of the repository describes each **deployment**: the
container image the steps run in, the ordered **steps**, and the typed,
validated **variables** the steps need. From that file Keel renders a proper
form, stores each **target's** values encrypted, runs the steps in Docker with
live logs, and captures **outputs** when a run succeeds.

The people who press the button do not need the tools, the credentials, or
the repository. They need a browser.

```yaml keel.yaml
version: 1

deployments:
  aws-production:
    description: Deploy the API to AWS ECS.
    environment:
      dockerfile: deploy/aws.Dockerfile
    steps:
      - name: Authenticate
        run: ./deploy/aws-login.sh
      - name: Deploy
        run: ./deploy/release.sh
    variables:
      AWS_ACCESS_KEY_ID:
        secret: true
        validation: {pattern: "AKIA[0-9A-Z]{16}"}
      AWS_REGION:
        type: select
        default: us-east-1
        options: [us-east-1, {value: eu-west-1, label: Europe (Ireland)}]
```

## The building blocks

  <Card title="Variables" icon="sliders" href="/concepts/variables">

## Two editions, one engine

Keel ships as two binaries that share the same engine and the same UI.

| | **Keel Dev** (`keel dev`) | **Keel Cloud** (`keel-cloud`) |
|---|---|---|
| Where it runs | your machine, one repository | your server, many repositories |
| State | `.keel/dev.db` in the repository (SQLite) | PostgreSQL |
| Users | just you | organizations, roles, scopes, invites |
| Repositories | the directory you run it in | connected by git URL or through a GitHub App |
| Continuous deployment | — | push-triggered auto-deploys via GitHub App webhooks |

Start with Keel Dev to author and test a `keel.yaml`. Move to Keel Cloud when
more than one person needs to deploy, or when deploys should happen on push.

<Note>
  Keel executes deployment steps with Docker. Runs happen on the machine that
  runs Keel — your laptop for Keel Dev, the server for Keel Cloud — never on a
  hosted service you do not control.
</Note>
